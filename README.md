# 3D-конфигуратор кабины лифта — реализация пп. 4 и 6 ТЗ

React-компонент `<ElevatorConfigurator />` со визуализацией на **Three.js**,
реализующий:

- **Раздел 4 ТЗ «СТРУКТУРА МАТЕРИАЛОВ»** — полный набор параметров
  конфигурации кабины (модели, габариты, тип кабины, двери, стены, вставки,
  потолок, пол, углы, плинтус, приказной пост, аксессуары, двери кабины и
  шахты, лифтовой холл) с точным соблюдением количества вариантов из ТЗ.
- **Раздел 6 ТЗ «ТРЕБОВАНИЯ К 3D-МОДЕЛЯМ»** — качество визуализации:
  корректные отражения, реалистичное мягкое освещение, отсутствие потери
  качества при масштабировании, высокая детализация материалов.

## Быстрый старт (демо)

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # прод-сборка в dist/
npm run lint     # ESLint (airbnb config, п. 2.8 ТЗ)
```

## Структура проекта

```
src/
  config/
    cabinCatalog.js         # каталог опций — раздел 4 ТЗ (дата-driven)
  three/
    SceneEngine.js           # Three.js-движок — раздел 6 ТЗ
  hooks/
    useCabinConfigurator.js  # состояние выбора + сборка конфига для сцены
  components/
    ElevatorConfigurator.jsx # корневой компонент (панель + 3D-вьюпорт)
    ElevatorConfigurator.css
    controls/
      OptionButtons.jsx      # выбор из именованного списка
      SwatchGrid.jsx         # выбор материала/цвета (свотчи)
      OptionSection.jsx      # свёртываемая секция панели
  App.jsx / main.jsx          # точка входа для локального демо (Vite)
```

## Как использовать компонент в проекте сайта

```jsx
import ElevatorConfigurator from './components/ElevatorConfigurator';

function ConfiguratorPage() {
  return <ElevatorConfigurator />;
}
```

Компонент самодостаточен: не делает сетевых запросов, вся логика — на
клиенте (соответствует п. 2.3 ТЗ «Автономное функционирование продукта»
и п. 2.8 «SPA / Client-side only»).

### Пункт 6 — «ТРЕБОВАНИЯ К 3D-МОДЕЛЯМ» (`src/three/SceneEngine.js`)

| Пункт ТЗ | Реализация |
|---|---|
| 6.1 Отражающие поверхности | `MeshPhysicalMaterial` + IBL-окружение через `PMREMGenerator`/`RoomEnvironment` (`_initEnvironment`); зеркало — `metalness:1, roughness:0.02`; хромированные элементы (углы, приказной пост, дверные полотна) — повышенный `metalness`/`clearcoat` |
| 6.2 Освещение | Трёхточечная схема `key + fill + hemisphere` (`_initLights`), мягкие тени `PCFSoftShadowMap` с `shadow.radius`, `ACESFilmicToneMapping` — без пересветов/чрезмерных затемнений |
| 6.3 Качество при зуме | Zoom реализован только сменой позиции камеры (`OrbitControls`), не масштабом геометрии; `renderer.setPixelRatio` пересчитывается при resize под `devicePixelRatio`; canvas не растягивается CSS |
| 6.4 Детализация | Анизотропная фильтрация текстур (`texture.anisotropy = maxAnisotropy`), корректное цветовое пространство (`SRGBColorSpace` для diffuse, линейное — для normal/roughness/metalness карт), повышенная сегментация геометрии со скруглениями (купольная камера, поручень) |

## Важные ограничения демонстрационной версии

Заказчик передаёт исходные 3D-модели и текстуры отдельно (п. 2.1 ТЗ) уже
после заключения договора. Пока этих материалов нет, геометрия кабины и
её элементов построена **параметрически** (боксы/цилиндры/сферы на основе
выбранных габаритов), а материалы отделки — это цветовые заглушки
(`color/roughness/metalness` в `cabinCatalog.js`).

Архитектура подготовлена так, чтобы подключение реальных ресурсов не
требовало переписывания кода:

- В каждом объекте материала предусмотрены поля `map/normalMap/
  roughnessMap/metalnessMap` — достаточно указать путь к файлу текстуры,
  `SceneEngine.createMaterial` сам подгрузит её с анизотропной
  фильтрацией и корректным цветовым пространством.
- Геометрию кабины (`_buildWalls`, `_buildDoors`, `_buildCorners` и т.д.)
  можно заменить на загрузку `.glb/.gltf`-моделей (`GLTFLoader`) без
  изменения остального кода — контракт `buildCabin(config)` останется
  прежним.
- Полная матрица взаимоисключений элементов (п. 4.16 ТЗ) поставляется
  Заказчиком отдельно; точка расширения — `useCabinConfigurator`
  (функция для проверки `isOptionDisabled`, сейчас все опции внутри
  структурных ограничений модели доступны).

Также в компоненте не реализована часть раздела 3 ТЗ (свободный/
внутренний обзор, фиксированные ракурсы, предупреждающий диалог сброса
конфигурации при смене модели, сохранение в PNG/PDF/JSON, форма заявки) —
она не входила в переданное задание (пп. 4 и 6) и потребует отдельной
проработки по прочим разделам ТЗ.

## Управление памятью (п. 2.8 ТЗ)

`SceneEngine` при каждой перестройке кабины и при `destroy()` (вызывается
из `useEffect`-cleanup компонента) обходит дерево сцены и вызывает
`.dispose()` для всех geometries, materials и текстур, отменяет
`requestAnimationFrame` и отключает `ResizeObserver` — это предотвращает
утечки RAM/VRAM при многократном переключении конфигураций.
