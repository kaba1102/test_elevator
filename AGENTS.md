# AGENTS.md

Руководство для AI-агентов и разработчиков, работающих с этим репозиторием.
Описывает назначение проекта, архитектуру, конвенции кода и правила, которые
нельзя нарушать при внесении изменений.

---

## 1. Что это за проект

Демонстрационный **3D-конфигуратор кабины лифта**: React-компонент
`<ElevatorConfigurator />` с визуализацией на Three.js.

Реализованы два раздела технического задания:

- **Раздел 4 ТЗ «Структура материалов»** — полный набор параметров
  конфигурации кабины (модель, габариты, тип кабины, двери, стены, вставки,
  потолок, пол, углы, плинтус, приказной пост, аксессуары, двери кабины и
  шахты, лифтовой холл) с точным количеством вариантов.
- **Раздел 6 ТЗ «Требования к 3D-моделям»** — качество визуализации:
  физически корректные отражения, мягкое освещение, отсутствие потери
  качества при зуме, высокая детализация материалов.

Компонент **самодостаточен**: вся логика на клиенте, сетевых запросов нет.
Раздел 3 ТЗ (обзоры, ракурсы, сохранение PNG/PDF/JSON, форма заявки) в
проекте **не реализован** — это ожидаемо, не добавляйте его «попутно».

## 4. Архитектура и поток данных

```
cabinCatalog.js  ──►  useCabinConfigurator()  ──►  ElevatorConfigurator.jsx  ──►  SceneEngine
 (данные, ТЗ 4)        (состояние + resolvedConfig)      (панель + canvas)          (3D, ТЗ 6)
```

Однонаправленный поток, без глобального стора, контекста и внешних
state-менеджеров:

1. [`src/config/cabinCatalog.js`](src/config/cabinCatalog.js) — единственный
   источник данных обо всех опциях и материалах. Экспортирует константы-
   массивы и lookup-хелперы [`findById()`](src/config/cabinCatalog.js:429),
   [`getWallParts()`](src/config/cabinCatalog.js:440).
2. [`src/hooks/useCabinConfigurator.js`](src/hooks/useCabinConfigurator.js) —
   владеет состоянием выбора (`state`), отдаёт экшены (`actions`) и
   вычисляет `resolvedConfig` — **единственный контракт** между UI и 3D.
3. [`src/components/ElevatorConfigurator.jsx`](src/components/ElevatorConfigurator.jsx) —
   рендерит панель управления и `<canvas>`; создаёт/уничтожает `SceneEngine`
   в `useEffect`, перестраивает кабину при изменении `resolvedConfig`.
4. [`src/three/SceneEngine.js`](src/three/SceneEngine.js) — класс, инкапсулирующий
   всю работу с Three.js: рендерер, сцена, камера, IBL, свет, контролы,
   построение геометрии и освобождение ресурсов.

Точка входа демо: [`index.html`](index.html) → [`src/main.jsx`](src/main.jsx) →
[`src/App.jsx`](src/App.jsx). В реальном проекте `App.jsx` не нужен:
`<ElevatorConfigurator />` встраивается в страницу сайта Заказчика.

### Структура файлов

```
src/
  config/cabinCatalog.js          каталог опций и плейсхолдер-материалов (ТЗ 4)
  three/SceneEngine.js            Three.js-движок (ТЗ 6)
  hooks/useCabinConfigurator.js   состояние выбора + сборка resolvedConfig
  components/
    ElevatorConfigurator.jsx      корневой компонент (панель + вьюпорт)
    ElevatorConfigurator.css      все стили компонента
    controls/OptionSection.jsx    свёртываемая секция (<details>/<summary>)
    controls/OptionButtons.jsx    выбор из именованного списка
    controls/SwatchGrid.jsx       выбор материала/цвета по свотчам
  App.jsx / main.jsx              демо-точка входа (Vite)
```

## 5. Соглашения по коду

### Стиль

- 2 пробела, одинарные кавычки, точка с запятой, trailing comma в
  многострочных литералах (как в существующем коде).
- Только `const`/`let`, стрелочные функции, `export default` для компонентов
  и хуков, именованные экспорты для каталога и хелперов.
- Файлы компонентов — `PascalCase.jsx`; хуки — `useXxx.js`; остальное —
  `camelCase.js`. **JSX допускается только в файлах `.jsx`**
  (`react/jsx-filename-extension`).
- `prop-types` отключён (`react/prop-types: off`) — не добавляйте PropTypes.
- `react/react-in-jsx-scope` отключён — `import React` в `.jsx` всё равно
  присутствует по традиции проекта, сохраняйте единообразие.
- CSS: БЭМ (`configurator__panel`, `option-button--selected`,
  `swatch__check`). Новые стили — только в `ElevatorConfigurator.css`.

### Документация в коде

- Комментарии и JSDoc-заголовки — **на русском языке**.
- В шапке файла — блок с назначением и ссылкой на пункт ТЗ.
- Секции внутри `SceneEngine` разделяются комментариями-линейками
  (`// ---- ... ----`). Сохраняйте этот стиль.
- При реализации требования ТЗ указывайте номер пункта в комментарии
  (например, `// 6.2: мягкие тени`).

### React

- Только функциональные компоненты и Hooks; классовых компонентов нет.
- Состояние — локальное (`useState`), производные значения — `useMemo`,
  сеттеры — `useCallback`. Не мутируйте объекты состояния: всегда
  возвращайте новый объект через спред.
- Не создавайте новых зависимостей без необходимости: в проекте нет
  роутера, UI-библиотек, стейт-менеджеров и i18n.
- Доступность обязательна: `aria-label`, `aria-pressed`, семантические
  `<section>`/`<details>`/`<button>`, `type="button"` у кнопок.
- Тяжёлые операции (построение геометрии, dispose) выполняются **вне**
  `requestAnimationFrame`-цикла — только в `useEffect` по факту изменения
  конфигурации.

## 6. Инварианты предметной области (ТЗ 4)

Эти правила нельзя нарушать — на них завязаны и UI, и 3D-сцена.

1. **Количество вариантов фиксировано ТЗ.** Не «оптимизируйте» и не
   округляйте: 4 модели, 3 габарита, 2 типа кабины, 3 типа дверей, 24
   отделки стен, 3 RAL вставок, 6 потолков × 2 форм-фактора × 16
   материалов, 9 полов, 24 угла, 19 плинтусов, 18/4/4 (Тип I) и 1/1/1
   (Тип II) для приказного поста, 4 зеркала, 4 поручня + 10 RAL, 24 двери
   кабины, 24 двери шахты, 22 вызывных поста, 4 табло.
2. **Флаги модели** `hasInserts` / `hasCorners` / `hasPlinth` управляют
   тремя вещами одновременно:
   - условным рендером секции в панели
     ([`ElevatorConfigurator.jsx`](src/components/ElevatorConfigurator.jsx:109));
   - обнулением соответствующего материала в `resolvedConfig`
     ([`useCabinConfigurator.js`](src/hooks/useCabinConfigurator.js:187));
   - условным построением геометрии в `buildCabin`
     ([`SceneEngine.js`](src/three/SceneEngine.js:253)).
     При добавлении подобного флага меняйте **все три места**.
3. **Тип кабины меняет состав стен.** `getWallParts(entryTypeId)` возвращает
   `left/right` для проходной и `back/left/right` для непроходной. Отделка
   стен хранится как словарь `wallMaterialByPart` по `part.id`; при смене
   типа кабины набор ключей пересобирается, лишние отбрасываются.
4. **Согласованность выбора.** При смене модели сбрасываются недоступные
   опции, при смене типа приказного поста — `bodyId`/`displayId`/`buttonsId`
   (у Типа II дисплея и кнопок нет). Новые зависимости между опциями
   добавляйте в соответствующие `set*`-колбэки хука, а не в компонент.
5. **Взаимоисключения (п. 4.16 ТЗ)** полностью Заказчиком ещё не переданы.
   Точка расширения — `isOptionDisabled` в `useCabinConfigurator`; не
   размазывайте правила совместимости по UI.
6. **Единицы измерения.** В каталоге габариты — **миллиметры**; в
   `SceneEngine` они переводятся в метры через `MM_TO_M = 0.001`. Не
   смешивайте единицы в одном слое.

## 7. Требования к 3D (ТЗ 6)

`SceneEngine` — единственное место, где разрешено работать с Three.js.
Не импортируйте `three` в компонентах и хуках.

- **Материалы** создаются только через
  [`createMaterial(spec, overrides)`](src/three/SceneEngine.js:191) —
  `MeshPhysicalMaterial` с корректными `roughness`/`metalness`/`envMapIntensity`.
  Зеркала и хром — высокий `metalness` и низкий `roughness`, а не «плоская
  заливка».
- **Освещение** — трёхточечная схема key/fill/hemisphere + IBL из
  `RoomEnvironment` через `PMREMGenerator`. Не добавляйте свет «на глаз»
  без необходимости и не отключайте `ACESFilmicToneMapping` /
  `PCFSoftShadowMap` — это прямые требования ТЗ.
- **Зум** — только перемещение камеры (`OrbitControls`), никогда не масштаб
  геометрии и не CSS-трансформация canvas. `pixelRatio` пересчитывается в
  `resize()`.
- **Текстуры** загружаются через `_loadTexture(path, colorSpace)`:
  `SRGBColorSpace` для diffuse (`map`), `NoColorSpace` для
  normal/roughness/metalness карт; анизотропия — `maxAnisotropy`.
- **Анимационный цикл** (`_animate`) не должен создавать объекты, материалы
  и геометрию — только `controls.update()` и `render()`.
- **Параметрическая заглушка.** Пока Заказчик не передал `.glb/.gltf` и
  текстуры (п. 2.1 ТЗ), геометрия строится из примитивов. Замена на
  `GLTFLoader` не должна менять публичный контракт `buildCabin(config)`.

## 8. Управление памятью (критично)

Каждая пересборка кабины создаёт новые geometry/material/texture. Без
освобождения это утечка VRAM.

- [`_disposeCabinGroup()`](src/three/SceneEngine.js:585) обходит дерево и
  вызывает `.dispose()` для геометрий, материалов и текстур.
- [`destroy()`](src/three/SceneEngine.js:601) отменяет
  `requestAnimationFrame`, отключает `ResizeObserver`, освобождает
  cabin-группу, загруженные текстуры, environment-текстуру, `PMREMGenerator`,
  контролы и рендерер. Вызывается из cleanup в
  [`ElevatorConfigurator.jsx`](src/components/ElevatorConfigurator.jsx:41).
- **Правило:** любой новый ресурс Three.js обязан попадать либо в дерево
  `cabinGroup`, либо в `loadedTextures`, иначе он не будет освобождён.
  Новый глобальный ресурс — обязательно освободить в `destroy()`.
- Не кэшируйте материалы «на будущее» между пересборками без явного
  управления их жизненным циклом.

## 9. Контракт каталога материалов

Каждый материал — самостоятельный объект:

```js
{
  id,            // уникальный строковый id, используется как значение выбора
  name,          // человекочитаемое имя (русский)
  color,         // hex-заглушка
  roughness,     // 0..1
  metalness,     // 0..1
  map,           // путь к текстуре или null
  normalMap,     // путь к текстуре или null
  roughnessMap,  // путь к текстуре или null
  metalnessMap,  // путь к текстуре или null
}
```

- Серии генерируются хелперами `makeMaterialSeries()` и `makeRalSeries()`.
  Не создавайте материалы вручную «поштучно», если нужна серия.
- Реальные текстуры подключаются **только** заполнением полей `*Map` —
  структура каталога и код `SceneEngine` при этом не меняются.
- `id` — стабильный ключ: он попадает в `state`, `resolvedConfig` и
  используется в условиях (`ceiling-mirror-frame`, `panel-type-1` и т.д.).
  Менять существующие `id` нельзя без синхронного обновления всех условий.
- Ограничение текущей реализации `createMaterial`: из `overrides`
  учитываются `envMapIntensity`, `clearcoat`, `clearcoatRoughness`,
  `transmission`, `emissive`, `emissiveIntensity`, `thickness`.
  `roughness`/`metalness` из `overrides` **игнорируются** — задавайте их в
  спеке материала каталога либо расширяйте `createMaterial` осознанно.

## 10. Чек-лист добавления новой опции

1. Добавить данные в [`cabinCatalog.js`](src/config/cabinCatalog.js) с
   уникальными `id` и русским `name`; экспортировать константу.
2. Добавить состояние и сеттер в `useCabinConfigurator`, включить значение в
   `state`, `actions`, `catalog` и (если влияет на сцену) в
   `resolvedConfig`.
3. Отрисовать секцию в `ElevatorConfigurator.jsx` через `OptionSection` +
   `OptionButtons`/`SwatchGrid`; при зависимости от модели/типа —
   обернуть в условие.
4. Учесть опцию в `SceneEngine.buildCabin` (и в `_disposeCabinGroup`, если
   создаётся отдельный ресурс).
5. Обновить карту соответствия ТЗ в [`README.md`](README.md).
6. Прогнать `npm run lint && npm run build` и проверить сцену в браузере.

## 11. Известные ограничения и точки расширения

- **Плейсхолдеры вместо реальных материалов**: `color/roughness/metalness`
  в каталоге — заглушки, текстуры (`*Map`) равны `null`.
- **Параметрическая геометрия** вместо моделей Заказчика (`GLTFLoader`
  подключается в `SceneEngine` без смены контракта).
- **Матрица взаимоисключений (п. 4.16)** не передана — см. `isOptionDisabled`.
- **`CEILING_FORM_FACTORS`** экспортирован, но панель использует локальный
  массив форм-факторов; `DOME_CAMERA_VARIANT` экспортирован, но не входит в
  `catalog` хука. При доработке приведите UI к данным каталога, а не
  дублируйте списки в JSX.
- **Раздел 3 ТЗ** (свободный/внутренний обзор, фиксированные ракурсы,
  предупреждение при сбросе конфигурации, экспорт PNG/PDF/JSON, форма
  заявки) отсутствует намеренно.
- **Тестов нет**: регрессии проверяются вручную в браузере (`npm run dev`)
  и через `lint`/`build`. Если добавляете тесты — согласуйте инструмент,
  не подключайте фреймворк «молча».
